# CHECKLIST.md — ручной гейт PR

**Сфера:** проверка перед merge — только то, чего не видит автоматика.
**Обновлено:** 2026-09-03.

## Что проверяется автоматически — вручную не дублировать

Эти пункты закрыты инструментами. Не переписывай их сюда и не проверяй глазами.

**pre-commit (локально, до коммита):**
- `gitleaks` — секреты и ключи в diff
- `ruff` — линт и формат
- `pytest` — тесты, включая валидацию всех схем из `SCHEMAS.md`

**GitHub Actions (на PR):**
- прогон тестов и линтера на чистом окружении
- ревью изменений через `anthropics/claude-code-action`

Красный CI или незакрытое замечание ревьюера — PR не мерджится. Отдельного пункта
об этом ниже нет намеренно.

## Ручная проверка перед merge

- [ ] Менялись `QUERIES.md`, промпты или веса ранжирования → приложен замер recall@5
      до/после (`eval/{date}.json`) и есть запись в `decisions_log.md`.
      Ухудшение recall@5 без обоснования — основание откатить.
- [ ] Появился новый файл в репозитории → есть запись в `decisions_log.md`.
- [ ] Появился новый файл документации → у него одна сфера, строки «Сфера:» и
      «Обновлено:», объём ≤ 200 строк, обновлена таблица «Документация» в `CLAUDE.md`.
- [ ] Между файлами документации нет расхождений в числах и правилах:
      лимиты, пороги, веса, цены, число файлов, часы peak/off-peak.
      Число, встречающееся в двух файлах, должно совпадать побайтово.
- [ ] Стоимость скана осталась в коридорах: ≤ 0,15 $ off-peak, ≤ 0,30 $ peak.
      Если изменился объём контекста слоёв — пересчитать таблицу в `ARCHITECTURE.md`.
- [ ] В diff нет клонирования репозиториев и исполнения чужого кода —
      ни `git clone`, ни `subprocess` над скачанным, ни установки чужих зависимостей.
- [ ] Системные промпты и их версии не менялись автоматически: правка промпта — это
      **новый** файл `src/scout/prompts/.../v{N+1}.md` плюс `PROMPT_VERSIONS`,
      существующие версии не редактируются.
- [ ] Новое правило в `CLAUDE.md` добавляется только после **второго** повторения
      инцидента. Первое повторение — запись в `decisions_log.md` или кейс в golden-set.

## Дополнительно — если PR трогает Слой 2 или отчёт

- [ ] Детектор регургитации на месте: поля `AuditResult` не содержат фрагментов
      исходного кода длиннее 120 символов.
- [ ] Ни один кандидат с `copyleft: strong` или `spdx_id: null` не получил вердикт `USE`.
- [ ] У каждого кандидата в отчёте заполнен лицензионный паспорт и непустой `provenance`.

## Правило применения

Пункт отмечен «нет» без обоснования в описании PR — **не мерджить**.
Обоснование в PR — это одна-две строки: почему в этом случае пункт неприменим.
Обоснование «сделаю в следующем PR» не принимается для пунктов о промптах,
клонировании и лицензиях.
