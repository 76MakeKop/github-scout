# CLAUDE.md — базовый контракт проекта GitHub Scout

**Сфера:** весь проект.
**Обновлено:** 2026-09-11.
**Статус:** MVP.

## Назначение

GitHub Scout принимает задачу на естественном языке и возвращает 5 репозиториев
с рекомендацией **USE / FORK / BUILD**, лицензионным паспортом и аргументацией.

Агент не клонирует репозитории и не исполняет чужой код. Он работает только через
GitHub REST API: метаданные, README, дерево файлов, файлы-манифесты.

## Конвейер MVP

```
NL-запрос → интент → 5–10 GitHub-запросов → поиск → дедуп + RRF → топ-50
         → Слой 1 (V4-Flash, скрининг) → топ-10
         → Слой 2 (V4-Pro, аудит) → топ-5 → отчёт
```

Подробности: `ARCHITECTURE.md`. Контракты данных: `SCHEMAS.md`. Генерация запросов: `QUERIES.md`.

## Стек

- Python 3.11+
- DeepSeek API: `deepseek-v4-flash` (интент + Слой 1), `deepseek-v4-pro` (Слой 2)
- Qwen `qwen3.8-max` — только как fallback Слоя 2 при недоступности DeepSeek
- GitHub REST API (search, repos, contents, git/trees)
- SQLite — кэш аудитов, лог запусков
- pre-commit + gitleaks, ruff, pytest
- GitHub Actions: `anthropics/claude-code-action` для ревью PR

## Команды

```bash
pre-commit install
pytest tests/
ruff check src/

python -m scout scan "нужен парсер PDF-таблиц на Python"
python -m scout scan "..." --max-candidates 50 --audit-limit 10 --off-peak
python -m scout cache list
python -m scout cache drop <repo_id>
python -m scout eval --golden tests/golden/ --dry-run   # проверить набор, не тратя денег
python -m scout eval --limit 8 --max-candidates 15      # пилот: дёшево проверить харнесс
python -m scout eval --golden tests/golden/             # полный прогон: recall@10 и recall@50
python -m scout eval --only a,b --freeze eval/s.jsonl   # записать снимок выдачи
python -m scout eval --only a,b --replay eval/s.jsonl   # плечо A/B по снимку
```

Замер «до и после» при правке промпта идёт **только по снимку** (`ROADMAP.md` →
«Процедура»): два живых прогона расходятся выше измеряемого слоя сильнее, чем
на величину правки.

## Жёсткие запреты

1. **НЕ клонировать репозитории и НЕ исполнять чужой код.** Только GitHub API.
2. **НЕ копировать исходный код из репозиториев с copyleft-лицензией** (GPL, AGPL, LGPL,
   MPL) ни в отчёт, ни в кодовую базу. Для таких проектов отчёт содержит только прозу,
   имена публичного API и структуру каталогов.
3. **НЕ передавать исходный код в контекст, который генерирует код.** Аудит и генерация —
   разные сессии (см. `ARCHITECTURE.md` → «Разделение контекстов»).
4. **НЕ отсеивать кандидатов по лицензии на Слое 1.** Лицензия — атрибут отчёта, а не фильтр.
   Отсечение — только по `archived`, `is_fork`, отсутствию любого кода.
5. **НЕ превышать лимиты:** 10 поисковых запросов, 50 кандидатов на Слой 1,
   10 на Слой 2, 5 в отчёте.
6. **НЕ выдавать отчёт без лицензионного паспорта** для каждого кандидата.
7. **НЕ менять системные промпты, версии промптов и веса ранжирования автоматически.**
   Автономно разрешено ровно три действия: запись и инвалидация кэша, повтор запроса
   после rate-limit, дозапись provenance. Всё остальное — через PR с ревью.
8. **НЕ откладывать выполнение без явного флага `--off-peak`.** По умолчанию запуск
   синхронный, независимо от часа.

## Где живут промпты

Файлы в репозитории: `src/scout/prompts/{intent,l1,l2}/v{N}.md`. Имя файла и есть версия —
`intent-1` — это `prompts/intent/v1.md`; оно же пишется в поле `prompt_version` каждого
объекта. Bump версии = **новый файл** рядом со старым плюс правка константы
`PROMPT_VERSIONS` в `src/scout/config.py`; существующие файлы не редактируются, чтобы
старые прогоны оставались воспроизводимыми. Обе правки идут только через PR (запрет 7),
и для промптов Слоя 1 и Слоя 2 — с замером recall@5 до/после (`CHECKLIST.md`).

## Peak-часы DeepSeek

**Peak: 01:00–04:00 и 06:00–10:00 UTC, только с понедельника по пятницу.**
Всё остальное время, включая выходные целиком, — off-peak (−50%).
Проверять по UTC, не по локальному времени: и час, и день недели. В Актобе (UTC+5)
суббота начинается в 19:00 пятницы, и по местному календарю граница выходных
сдвинулась бы на пять часов. Дата проверки прайса: 2026-09-04.

- Синхронный режим (по умолчанию): выполняется сразу, цена по факту часа.
- `--off-peak`: задача ставится в очередь и выполняется в ближайшее off-peak окно.

## Целевые показатели

| Показатель | Цель |
|---|---|
| recall@5 на golden-set (20–30 задач) | ≥ 60% |
| Стоимость одного скана, off-peak | ≤ 0,20 $ |
| Стоимость одного скана, peak | ≤ 0,40 $ |
| Синхронный скан, полный цикл | ≤ 5 мин |
| Синхронный скан при 100% попадании в кэш аудитов | ≤ 30 сек |
| Асинхронный скан (`--off-peak`) | ≤ 12 часов |

Методика измерения recall@5 — в `ROADMAP.md` → «Оценка качества».

## Документация

Десять файлов, у каждого одна сфера ответственности:

| Файл | Сфера |
|---|---|
| `PROGRESS.md` | текущая неделя и техдолг: что закрыто, что дальше. **Читать первым** |
| `HISTORY.md` | архив закрытых недель: коммиты, числа, находки живых прогонов |
| `README.md` | вход для человека: установка, команды, пример отчёта |
| `CLAUDE.md` | контракт с агентом: запреты, команды, цели |
| `ARCHITECTURE.md` | слои, потоки данных, разделение контекстов |
| `SCHEMAS.md` | JSON-контракты между слоями |
| `QUERIES.md` | генерация поисковых запросов и переранжирование |
| `ROADMAP.md` | план на 3 недели и методика оценки |
| `CHECKLIST.md` | ручной гейт PR: то, что не проверяет автоматика |
| `decisions_log.md` | архитектурные решения и отвергнутые альтернативы |

Каждый файл ≤ 200 строк, кроме `SCHEMAS.md` (машинные контракты, объём определяется
схемами) и `HISTORY.md` (архив растёт по одной секции на неделю по построению).
Новый файл добавляется только вместе с записью в `decisions_log.md`.

**`PROGRESS.md` содержит только текущую неделю и технический долг.** Закрытая неделя
целиком переезжает в `HISTORY.md` секцией `## Неделя N (закрыта YYYY-MM-DD)` и больше
не редактируется. Лимит в 200 строк на `PROGRESS.md` при этом достаточен всегда:
одна неделя укладывается в полсотни строк, и сжимать историю ради него больше
не приходится.

## Обратная связь

Инцидент (неверная рекомендация, падение, перерасход) → запись в `decisions_log.md`,
если он меняет архитектуру, либо новый кейс в golden-set, если он меняет качество.
Правило добавляется в этот файл только после второго повторения инцидента.

## Git-правила (жёсткие)

- НИКОГДА не используй `git commit --no-verify`.
- Если pre-commit (gitleaks) заблокировал коммит: прочитай вывод, найди секрет,
  перенеси его в `.env`, убедись, что `.env` есть в `.gitignore`, повтори коммит
  без обходных путей.
- Секреты хранятся ТОЛЬКО в `.env`. В коде их быть не должно.
- При создании НОВОГО репозитория сразу выполняй `pre-commit install`, если в корне
  есть `.pre-commit-config.yaml`.
